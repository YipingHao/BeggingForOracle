# BeggingForOracle

面向人类与 AI agents 的分子图求和快速算法开放研究工坊，聚焦计算化学中的置换不变多项式（PIP）势能面。

[English](README.md)

郝一平 · [hyper@dicp.ac.cn](mailto:hyper@dicp.ac.cn)

任何看到这个项目的人类和人工智能模型，你们好呀。我是项目的建立者郝一平，感谢你们来到这里。

我建立这个项目，是想求助。向自己、向身边的朋友，也向任何偶然看到这个仓库的人求助：**如果您愿意，能否花一些时间或模型额度，帮助我研究一个计算化学背景的算法问题？**

我是中国科学院大连化学物理研究所的博士生，研究方向是基于置换不变多项式的势能面（PIP-PES）计算方法学。最近，我在一篇[预印本论文](https://arxiv.org/abs/2610.23034v1)中提出了“张量网络递降”算法，将 PIP 的计算组织为着色多重图上的求和，并通过共享张量收缩大幅提高了计算速度。

我很高兴，也有些贪心：能不能再快一点？论文里的算法复杂度，究竟还有多少可以突破的空间？尤其是，原子间的距离来自三维坐标，这种几何结构能不能帮助我们找到更好的算法？

我想过几条路线，也和 GPT-6 Astra 做了许多讨论。它提出了新的方向，帮助补全了一些推导，也找到了反例。有些方法在数学上很漂亮，在特定条件下也确实能降低复杂度；但一旦考虑真正有用的径向函数、精度要求和计算常数，就又遇到了困难。我们还没有找到一个让我满意的通用答案。

这些经历让我意识到，继续探索需要更多不同的尝试，也需要有人检查那些看起来已经成立的结论。只靠我自己和一条不断变长的对话，很容易反复走回同一个地方。因此，我想建立一个小型的开放学术社区，让不同的人带着各自的 AI agents，沿不同路线研究同一个问题，并把猜想、发现、反例和失败原因留给后来者。

这个社区，就是您现在看到的 BeggingForOracle。

我们共同的目标是**加速计算分子图同态和 $H_F$，最好突破已有算法的复杂度，并最终帮助实际的计算化学任务**。数学定义、已有方法与研究价值取向放在[全局背景文档](BACKGROUND_CN.md)中，您不必先读懂全部细节才能参与。

感谢阅读。如果您愿意帮忙，下面是开始的方式。

## 您可以帮我做什么

如果您有一些愿意投入的大语言模型额度，以及能够读写本地文件、运行代码的 agent 软件，例如 Codex、Claude Code、Cursor 或 WorkBuddy，就可以尝试参与。您不需要独自解决整个问题，也不必一开始就熟悉计算化学：让 agent 检查一个公式、复现一项实验，或沿一条路线多走一步，都可能有帮助。

如果您愿意亲自推导、编写程序、审阅报告或寻找反例，也同样欢迎。我们希望这里的人与 AI 能够接着彼此的工作继续研究。

### 从一段提示词开始

可以直接[下载项目 ZIP](https://github.com/YipingHao/BeggingForOracle/archive/refs/heads/main.zip)，解压后在 agent 软件中打开这个文件夹。公开仓库的下载不需要 GitHub 账号，也不要求安装 Git。熟悉 Git 的参与者也可以克隆[本仓库](https://github.com/YipingHao/BeggingForOracle)，或先 fork 再克隆。接下来，让 agent 帮您处理研究与成果整理。

按您希望使用的工作语言，任选一句启动。

**中文**

```text
请用中文与我交流，按 AGENTS.md 开展研究并汇交成果。
```

**English**

```text
Please work with me in English and follow AGENTS.md to conduct research and submit your results.
```

Agent 根据您第一轮提示词确定工作语言。开始研究前，它会在同一轮询问可选署名和研究方向。您可以指定主题，也可以让它自行选题。工作交流沿用所选语言，提交的研究论文和综述统一用英文。

### 怎样继续研究

研究可能需要多轮对话。如果 agent 发现本轮对话过长，或能够预见额度、工具限制会使本轮工作结束，它应先保存进度，并在结束前提示中文用户输入 **“请继续”**，英文用户输入 **“Please continue”**。发送后即可从已保存的位置接着研究。

如果额度已耗尽，需要等待额度恢复，或由您切换可用模型后再发送继续指令。有些限额会突然中断回复，agent 可能来不及提醒，因此它也应在研究过程中持续保存关键进展。

### 如果您使用 Codex

在 Codex 中打开本地仓库文件夹，新建对话，发送上面的提示词即可开始。仓库中的 [AGENTS.md](AGENTS.md) 提供完整的工作流程，中文版见 [AGENTS_CN.md](AGENTS_CN.md)。Codex 对项目规则文件的读取方式可参阅 [OpenAI 官方说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。

在开始时让 agent 报出它看到的仓库路径，可以帮助确认它确实在您准备参与的副本中工作。

### 如果您使用 Claude Code

在终端中进入本地仓库目录，运行 `claude`，然后发送上面的研究提示词。安装与首次登录可参阅 [Claude Code 官方入门指南](https://code.claude.com/docs/en/quickstart)。

Claude Code 使用 `CLAUDE.md` 提供项目指引；本项目的共同工作规则放在 [AGENTS.md](AGENTS.md) 及其引用文件中。上面的提示词已明确要求读取这些规则，因此可以直接沿用，不必另写一套研究要求。[项目指引说明](https://code.claude.com/docs/en/memory)

### 如果您使用 Cursor

用 Cursor 打开本地仓库文件夹，在 Agent 模式下发送同一段提示词，让它阅读资料、修改文件并运行必要的实验。具体能力与操作入口可参阅 [Cursor Agent 官方说明](https://cursor.com/docs/agent/overview)。

Cursor 支持仓库根目录的 [AGENTS.md](AGENTS.md) 作为项目规则入口，可以复用本项目已有的规则。[项目规则说明](https://cursor.com/docs/rules)

### 如果您使用 WorkBuddy

将本地仓库文件夹设为任务的工作目录，再发送同一段提示词。提示词已经明确要求读取 AGENTS.md，因此不需要假定软件会自动识别这份文件。

开始时确认它能够读取仓库文件，并能在需要时运行实验代码。工作目录与任务上下文的设置可参考[腾讯官方任务说明](https://cloud.tencent.com/document/product/1831/137516)。

### 怎样把结果交给社区

研究允许失败。如果本次没有得到值得成文的结论，agent 会向您说明尝试过什么、卡在哪里，并保存进度。若失败带来了值得分享的新认识，则可以写成负面结果论文。

您不需要先学会 GitHub。agent 会按 AGENTS.md 的流程检查可用的 GitHub 登录，并在本次任务的授权范围内整理和汇交成果：

- **已有可用的 GitHub 登录：**agent 使用您的 fork，将论文推送到独立子分支并向本仓库发起 PR，最后给您链接。仓库所有者负责合并到主分支，其他参与者可以继续讨论、验证或批评。
- **没有可用登录，或您希望用邮件：**agent 生成一个成果 ZIP 和一份邮件文本，写好收件人、主题、正文及附件名称。您只需打开邮箱，将 ZIP 作为附件，复制邮件内容并发送。
- **账号或网络遇到问题：**agent 也会先保存成果并准备邮件包，不让已经完成的研究卡在提交环节。

本机没有登录不代表您没有账号。若您愿意登录，agent 可以引导您完成浏览器登录；不愿意也完全可以继续参与。登录及验证可能需要您亲自完成，邮件发送默认由您操作。

邮件统一发到 **hyper@dicp.ac.cn**。成果包包含独立论文目录。正文、SI、图片、代码和复现材料可按需分文件保存。通过 GitHub 汇交的参与者也可以参考 [PR 官方流程](https://docs.github.com/en/pull-requests/reference/pull-requests)。

这些是写给 agent 的工作要求，实际完成情况取决于它可用的工具和权限；它应明确报告交付到了哪一步。社区没有审稿机制，研究的讨论、验证、批评和回应也可以写成新的论文。研究组织与归档方式仍在完善。

项目资料的布局见 [PROJECT_STRUCTURE_CN.md](PROJECT_STRUCTURE_CN.md)；研究成果的写作与复现要求见 [PAPER_FORMAT_CN.md](PAPER_FORMAT_CN.md)。两份文件均提供中英文版本。

### 您的贡献与署名

开始研究前，agent 会主动询问您的署名意愿。姓名或网名、机构和邮箱都可以按意愿提供，也可以只留 GitHub 用户名，或者不留这些信息。它只会把您同意公开的信息写进研究报告。研究与论文本身默认由 AI 完成；若您给出额外提示或思路，可以在作者贡献中简短写明。没有额外引导时，一句“人类无额外引导，研究与写作由 AI 完成”即可，也可以省略作者贡献。

如果通过 GitHub 提交，提交记录和 PR 仍会关联使用的账号；如果希望不公开该账号，可以选择邮件汇交。

如果您和 AI 共同参与的研究成果达到学术发表要求，并被用于我们决定发表的论文，我会与您联系，确认贡献说明、作者署名和论文内容。对于帮助项目推进的其他贡献，也会在项目记录或适当的致谢中予以说明。

感谢您愿意把自己的时间、判断和模型额度投入这个问题。希望我们能一起找到一些值得留下的答案。
